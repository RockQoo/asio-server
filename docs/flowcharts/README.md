# 플로우차트 규칙

이 폴더는 asio-server의 동작을 "한눈에" 볼 수 있는 HTML 다이어그램 모음이다. 코드를 안 읽고도
데이터/제어 흐름을 파악할 수 있게 하는 게 목적이라, 코드 설명(`CLAUDE.md`, `README.md`)과는
별개로 유지한다.

## 새 기능을 추가할 때

**기능이나 패킷 흐름을 새로 추가하면, 이 폴더에 HTML 페이지 하나를 같이 추가한다.**

1. `assets/style.css`를 그대로 `<link>`한다 (새 CSS를 만들지 않는다 — 스타일이 페이지마다
   달라지면 "한눈에 보기"라는 목적이 흐려진다).
2. 기존 페이지(`testclient-echo-move-chat.html`)의 구조를 그대로 따른다:
   - 상단에 `back-link`로 `index.html`로 돌아가는 링크
   - `legend`로 어떤 스레드/행위자가 등장하는지 뱃지 표시
   - `.flow` 안에 `.step`(client/io/logic 중 하나)을 순서대로 나열, 사이사이 `.connector`
   - 분기가 있으면 `.branch`(2컬럼 grid)로 나란히 보여주고 다시 하나로 합류
   - 맨 아래 `.callout`으로 핵심 불변식/주의사항 요약
3. `index.html`의 `index-list`에 새 페이지 링크를 추가한다.
4. **외부 리소스(CDN JS/폰트/이미지)를 쓰지 않는다** — 오프라인에서 더블클릭으로 열어봐야
   하는 로컬 문서다. Mermaid 같은 라이브러리를 쓰고 싶으면 로컬에 벤더링부터 하고, 그게
   여의치 않으면 지금처럼 순수 HTML/CSS로 그린다.

## 왜 코드 코멘트나 README 대신 여기에

`CLAUDE.md`/`README.md`는 텍스트로 읽는 문서고, 이 폴더는 **스레드 경계(I/O ↔ 로직)처럼
텍스트로는 잘 안 와닿는 흐름을 시각적으로** 보여주기 위한 것이다. 존 어피니티 라우팅처럼
"패킷이 어느 스레드에서 어느 스레드로 넘어가는지"가 핵심인 이 프로젝트 특성상, 스레드별로
색을 나눠서 보여주는 게 특히 유용하다.
