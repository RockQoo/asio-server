패킷 시퀀스 다이어그램

대표 기능이 어느 스레드를 거쳐 어디까지 가는지를 패킷 단위로 따라간다. 코드를 안 읽고도 흐름이 보이는 것이 목적이다.

C2ZMailAdd → DB 우편 하나를 넣을 때 Gateway·World·Zone 두 레인·DB 레인을 지나는 전 경로. 클라이언트 응답과 DB 저장이 같은 바이트에서 갈라지는 지점, 그리고 지금 끊겨 있는 자리. C2ZMailBuy — 트랜잭션과 역순 롤백 우편 지급 + 골드 차감을 한 UnitOfWork로 묶고, 잔액이 모자라면 역순으로 되돌린다. 호출부에 롤백 코드가 없는 이유. 존 핸드오프 존 경계를 넘는 이동. World가 라우팅 테이블 한 줄만 바꾸고, 클라이언트는 같은 연결을 유지한다. 스레드 간 이동과 프로세스 간 이동의 차이.

읽는 법

  • 세로선 하나 = 스레드(레인) 하나. 같은 서버라도 레인이 다르면 칸이 다르다 — 이 프로젝트에서 중요한 건 프로세스 경계만이 아니라 스레드 경계이기 때문이다.
  • 화살표 색 = 보낸 쪽 스레드. 상단 뱃지 색과 짝이 맞는다.
  • 네모 상자 = 그 레인 안에서 벌어지는 일(락 획득, 소멸자, 판정). 빨간 테두리는 실패/중단, 노란 테두리는 아직 구현되지 않은 자리다.
  • 점선 화살표 = 설계는 있으나 아직 호출되지 않는 경로.

패킷 번호 대역

패킷 id는 Shared/Protocol/Src/PacketId.h 하나로 통합돼 있고, 이름 앞 3글자가 발신 → 수신 방향이다(C2ZMailAdd = Client → Zone). 방향마다 1000 단위로 대역을 잘라서, 값 하나만 보면 어느 소켓의 패킷인지 판정된다. 규약 원문은 .claude/rules/packet-naming.md.
