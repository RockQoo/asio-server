WorldServer 라우팅 + DB

누가 어느 존에 있는지 아는 유일한 서버. 그리고 DB로 나가는 유일한 관문.

한 줄 요약

포트 셋을 열어(Gateway 9100 / Zone 9200 / 운영툴 9300) 클라이언트 패킷을 담당 존으로, 존이 올린 변경분을 DB로 보낸다. 존 이동은 여기 라우팅 테이블 한 줄로 끝난다.

스레드 구조 — 그룹 두 개

I/O 스레드 2개        소켓에서 바이트만 복사, ownerId를 훔쳐보고 큐에 넣는다
      ↓
BASIC 그룹 (8 레인)   owner = clientSessionId
      ├ Main 프로세서   클라이언트 라우팅 (ClientRegistry / ZoneLinkRegistry)
      └ Tool 프로세서   운영툴 명령
      ↓
DB 그룹 (4 레인)      owner = clientSessionId → UnitOfWork 스트림 적재 (블로킹 허용)
Main과 Tool이 한 그룹을 공유하는 이유는 둘 다 주인이 clientSessionId이기 때문이다. 주인이 같으면 같은 레인으로 가고, 그러면 운영툴이 만지는 대상과 그 사람의 일반 패킷이 같은 스레드에서 순서대로 처리된다 — 그래서 라우팅 테이블에 락이 없다.

DB 그룹을 따로 둔 이유

DB 호출은 블로킹이다. 라우팅 레인에서 같이 하면 쿼리 한 번이 그 레인에 걸린 모든 사람의 패킷을 멈춘다. 그래서 "막혀도 되는 일"만 모아 별도 그룹에 둔다.

이 수치는 설정 파일에서 온다

스레드 수·포트·주기는 config/world.cfg에서 읽는다. 값이 틀리면 기본값으로 넘어가지 않고 기동을 멈추고, 아무도 읽지 않은 키는 경고로 남는다(오타를 잡는 유일한 수단). 자세한 건 설정 파일 설계.

핵심 타입

타입역할락
ClientRegistryclientSessionId → (gatewaySession, 현재 zoneId)없음 — BASIC 레인 전용, 샤딩
ZoneLinkRegistryzoneId → (zoneSession, 담당 사각형)없음 — 같은 이유
AutoDbCommandSP 커맨드를 모았다가 소멸 시 한 번에 실행—
DbConnectionODBC 커넥션 하나. 레인 스레드마다 thread_local 1개없음 — 1:1이라 공유가 없다
ToolProcessor운영툴 전용 포트(9300)의 핸들러없음 — 다른 링크와 같은 스레드 규약

존 이동 = 라우팅 테이블 한 줄

존이 "이 사람이 내 사각형을 벗어났다"고 알려오면, World가 좌표로 대상 존을 찾아 clientRegistry_.SetZone(clientSessionId, 대상) 한 줄을 실행한다. 그게 핸드오프의 전부다. 클라이언트는 재접속도 재인증도 하지 않는다.

자세한 흐름: 존 핸드오프 시퀀스

DB로 나가는 길

존이 Z2WUnitOfWorkStream을 올리면 BASIC 레인을 거치지 않고 DB 그룹으로 직행한다 — 라우팅 상태를 전혀 건드리지 않기 때문이다. 
Z2WUnitOfWorkStream  →  dbGroup_.Post(Db, ownerId)
                          └ AutoDbCommand(ownerId, useTransaction = true)
                              ├ up_mails_upsert       (@is_trans_outside = 1)
                              ├ up_currencies_upsert  (@is_trans_outside = 1)
                              └ COMMIT   /  예외면 ROLLBACK
UnitOfWork 하나 = AutoDbCommand 하나 = 트랜잭션 하나. 여러 UoW를 모으지 않는다.

아직 안 된 것

  • Task → SP 호출 배선 — ApplyMailTask가 로그만 남긴다. 위 그림의 마지막 칸이 비어 있다
  • 콘텐츠 메모리 캐시 — 로그인 시 우편/재화를 적재해 존이 올린 Task를 대조(위조 검증)할 자리
  • 공통 콘텐츠 — 길드처럼 여러 존에 걸친 것이 들어올 자리

관련 문서

C2ZMailAdd → DBWorld가 ③·⑪ 구간에서 하는 일 DB 계층스키마·SP 규약·트랜잭션 ZoneServerWorld가 패킷을 넘기는 쪽
