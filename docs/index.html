asio-server 문서

C++23 / standalone ASIO 기반 MMORPG 서버 구현. 존 단위 스레드 어피니티로 락 없이 게임 상태를 처리한다.

전체 그림

Client ──▶ GatewayServer ──▶ WorldServer ──▶ ZoneServer ──▶ SQL Server
           (순수 릴레이)      (라우팅 + DB)    (게임 로직)
                                  ▲
                              GmTool (9300)
프로세스역할스레드
Gateway클라이언트 accept, 순수 릴레이I/O 2
World로그인, 라우팅, DB 관문, 공통 콘텐츠I/O 2 · Basic 8 · Db 4
Zone존/플레이어 권위 상태I/O 2 · LB 2 · BASIC 8 · TICK 2N+1 · BROADCAST 4 · TIMER 1

스레드 수와 포트는 config/*.cfg에서 읽는다 — 위 값은 기본 설정이다 (형식과 정책).

큐 그룹에 일을 넣는 길이 두 가지다. 주인(ownerId)을 주면 그 주인의 일이 겹치지 않고 보낸 순서대로 처리되고(asio::strand), 주지 않으면 남는 스레드가 집어간다. Zone은 전부 주인을 지정해 락 없이 돌고, World는 순서가 필요한 것만 지정한다 — 그래서 World의 전역 테이블은 Thread::Mutexed다.

서버별 문서

Client C#/MonoGame 시각 클라이언트. 눈으로 확인하는 것과, 지금 클라이언트가 메워주고 있는 서버의 빈자리. GatewayServer 클라이언트가 아는 유일한 서버. 게임 로직 0, I/O 스레드 2개. WorldServer 로그인의 끝점이자, 누가 어느 존에 있는지 아는 유일한 서버. 존 이동은 여기 한 줄로 끝난다. ZoneServer 레인 다섯, 담당 존마다 처리기 네 벌. 주인이 다르면 스레드가 다르다. DB 계층 스키마·SP 골격·트랜잭션. UnitOfWork 하나 = 트랜잭션 하나. 성능 점검표 부하를 걸어 어디서 무너지는지 재고, 무엇을 고칠지 정한 기준선.

패킷 시퀀스 다이어그램

C2WLogin — 로그인과 자동 가입 레인을 네 번 갈아탄다. 계정이 없으면 만들고, 우편·재화를 읽어 존까지 넘긴다. C2ZMailAdd → DB 우편 하나가 Gateway·World·Zone 두 레인·DB 레인을 지나는 전 경로. C2ZMailBuy — 역순 롤백 모델 두 개에 걸친 트랜잭션이 실패했을 때 되돌아가는 장면. 존 핸드오프 재접속 없이 존을 넘는다. 스레드 간 이동과 프로세스 간 이동의 차이.
